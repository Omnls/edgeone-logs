# 验收标准

本文件根据用户的「EdgeOne Pages 接收实时 HTTP 日志、存入 Blob、支持 522 与其他错误排查」目标制定。应用代码由请求路由为 `gpt-5.2` 的子代理编写，父代理只策划、审查和执行验证。实际后端模型未经运行时证实。

验收对象是本项目的实际 Cloud Functions 入口及存储副作用，不能仅以内部纯函数测试通过判定完成。新项目没有 Git 历史时，使用源码/配置/测试文件的 SHA-256 清单标识候选；报告与测试输出放在工作区外的临时验收目录。最终结果在实现冻结后填写。

| ID | Required | 可观察标准 | 执行面 | 验证方法 |
| --- | --- | --- | --- | --- |
| AC-01 | true | Pages 按官方文件路由找到默认函数入口，普通 context 使用实际 Blob SDK 初始化 | static/api | 检查 cloud-functions 路径和默认导出；从默认入口执行本地 Request，仅替换 SDK 存储传输 |
| AC-02 | true | 官方控制台原文格式化 JSON 样例、ISO8601 NDJSON、gzip 和 JSON 数组均可接收 | api/data | 使用官方61296/61300样例及确定性合成记录，断言200及完整存储内容 |
| AC-03 | true | 522、其他4xx/5xx和投递的正常状态均保留诊断信息 | api/data | 读回多种状态，核对RequestID、EdgeException、Origin状态/耗时等字段 |
| AC-04 | true | 相同重试不重复，RequestID相同但内容不同的记录不丢失 | api/data | 重复推送和WebSocket周期日志对照；核对对象与记录数 |
| AC-05 | true | 跨UTC小时记录能按各自小时检索；部分写失败后的重试可恢复 | api/data | 跨小时批次、注入一次存储失败、重试并读回各小时 |
| AC-06 | true | 无效批次、超限数据和存储错误不会得到虚假的成功确认 | api/data | 坏行/非法元素/无效时间/压缩超限/流读取超限/写失败；核对错误码和零写入或可重试状态 |
| AC-07 | true | 接收与管理权限独立，已配置的签名不能通过省略参数降级 | api | 未配置、错误密钥、权限互换、过期/未来/重复/缺失签名参数 |
| AC-08 | true | 明确敏感字段和URL中的查询凭据不出现在存储或响应中 | api/data | 合成标记覆盖嵌套Authorization/Cookie/body、查询串及Referer，核对实际写入对象 |
| AC-09 | true | 管理查询筛选有效，范围与分页如实报告，输入/读取/响应体有界 | api | 合法筛选、坏参数、页游标、读失败与预算超限，不把失败伪装成零结果 |
| AC-10 | true | 公开入口方法受限，所有成功和错误响应禁止缓存 | api | POST/GET/不支持方法、Content-Encoding与响应头检查 |
| AC-11 | true | 固定依赖可安装，语法检查覆盖真实入口，项目相关测试通过 | cli/static | 核对锁文件和脚本后运行最小充分check；记录Node版本、命令及退出码 |
| AC-12 | true | 文档给出可操作的配置、部署和522排查路径，准确区分平台事实与自设限制 | static | 对照官方资料、实际变量和路由；确认采样、回环、配额及未验证项 |
| AC-13 | false | 真实 EdgeOne 控制台投递并写入线上 Blob | api/data | 需要已部署项目及其环境配置；本次编写代码任务不自动登录、发布或写入生产 |

AC-13 未执行时只能声明「本地代码与入口契约已验证」，不能声明已接收真实日志或线上可用。没有用户提供的实际522日志，也不能从此项目实现推断既有故障的根因。
